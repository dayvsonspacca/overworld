# Overworld

The user's own Linux desktop environment, its dotfiles and the C# behind it, in one repository.

## Parts

Structural parts are named after Minecraft blocks and mechanics, apps after items that are ordinary words.

- **Bedrock** (`src/Overworld.Bedrock`): the core every part is built on, depending on nothing else in Overworld: operations and their catalog, results and errors, one JSON shape, and lending (`Lending`): an `ILoan` is one app's thing another app shows inside itself (its key, the app lending it, its title, whether it is live), and an `ILender` knows its app's things in what an operation gave back.
- **Chest** (`src/Overworld.Chest`): storage, the JSON files where Overworld keeps its data and the folder they live in.
- **Allay** (`src/Overworld.Allay`): agents anywhere in Overworld. What a conversation is in Overworld's words (prompts; replies made of moments, speech, thoughts, a plan, acts and their results, notices, requests; one outcome; the decisions a person hands back), what an agent and its sessions are (each agent with its own color), the brief an app hands a session once (context, rules, skills, tool servers, by address or by a command the agent starts) and rebriefs as a difference, the rules a reply keeps, which agents are hired with their mode, model and effort, in Allay's Chest folder, and the usage an agent that tells it reports (`Metering`). It holds **the service** (`Remote`): every chat lives in Allay's service, `overworld:allay serve`, on `overworld-allay.sock`, so an agent goes on when its window closes; an app reaches it with `AllayLink`. A chat is **kept** (saved by the service and caught up on, like Crafter's project chats) or **disposable** (never saved, ending with its app, opened by a `Lobby` in `Visits`). `Bells` turns an agent's requests into Bell notices.
- **Allay presentation** (`src/Overworld.Allay.Presentation`): the chat any app can show: the timeline, its entries and Markdown, and `Chats.ChatViewModel`, a whole disposable chat ready for a corner of any window.
- **Claude Code** (`src/Overworld.Allay.ClaudeCode`): the first concrete agent, translating Claude Code's stream into Allay's moments, and reading its plan's usage from `claude -p /usage` (no tokens spent, no session kept).
- **Web** (`src/Overworld.Web`): how every app draws its window. The app keeps its logic and view models in C#; `WebHost` and `Page` serve a page, and the **mirror** sends it the view models and every change (only objects that notify are sent by reference; dates go as ISO 8601), while the page runs commands, sets properties and invokes methods back. Pages are React and TypeScript built by Vite, in each app's `.Desktop/web`, as npm workspaces with two shared packages: **`@overworld/kit`** (`Web/Kit`: the hooks that read the mirror, the theme, the title bar, buttons, fields, a modal, `Prose`, the command palette with every shortcut (Ctrl+Shift+P, Ctrl+/), `AllayIcon`, and the `ItemFrame` that shows one app's thing inside another) and **`@overworld/chat`** (`Web/Chat`: the message list, permission and question cards, Markdown with highlighted code, loan views and `ChatBubble`, the chat in a corner).
- **Glass** (`src/Overworld.Glass`): the native window every app opens, a small Tauri program in Rust (`overworld-glass`) drawing the page with WebKitGTK on Wayland.
- **The ways in** (`src/Overworld.Cli`, `src/Overworld.Mcp`, `src/Overworld.Hosting`): how people and agents reach operations: a CLI (operations reached by their words, like `overworld pins add` for `pins-add`; options that take an object read it as JSON, and ids are read as Guids), MCP (stdio, as `<app> mcp`, and an HTTP host that serves tools to agent sessions), and `AppHost`, the entry point that picks one or opens the window.
- **Themes** (`config/overworld/themes`): the colors, type sizes, radii and spacing the shell and the apps share, one folder per theme with a dark and a light JSON file, Amethyst first. Seed links the folder as `~/.config/overworld/themes` and the theme worn as `~/.config/overworld/theme.json`, the only file either side reads; Dye applies another one, and every window wears it as soon as the beacon signals `theme`.
- **Dye** (`apps/Dye`): palettes as a gallery of cards and Overworld's themes, each previewed in an app and the shell with its colors by role and applied in a click (`overworld:dye themes list | show | save | apply`; saving lights `themes`), and the profile picture the shell shows (lights `profile`). It lends its palettes and themes to other apps (`DyeLender`). Its window has a chat in a bubble (Ctrl+J), briefed by `Agents/DyeBrief` with Dye's own operations through `dye mcp`, reads free and writes asked first.
- **Allay app** (`apps/Allay`): the app to hire agents for every app, see whether each is ready, choose the mode, model and effort it starts with and see its usage (`overworld:allay agents list | check | hire | configure | usage`, lighting `agents`); its program is also Allay's service (`overworld:allay serve`).
- **Crafter** (`apps/Crafter`): the user's AI-coding app. Its logic holds projects, axioms, summaries, todos, preferences, the skills library, chats (each stamped `touched` when kept), prompts built from what was typed, a workshop that opens a project's chat as a kept chat in Allay's service, briefed with the project (`ProjectBrief`) and handed Crafter's tools (`crafter tools <folder>` by command, with Painting's and Dye's borrowed, and `crafter-chat` on the window for rename-chat and the proposals), and its bells. It opens on a **home**: the projects as cards (branch, last line, agents working or waiting on the person, chats, todos), adding a project, preferences, the chats talked in last, and a disposable chat in a bubble (`Sessions/HomeBrief`, `crafter mcp`, in the projects root) that makes, clones and adds projects; Crafter lists its projects again when that agent is done. A project has its chats as one thread with a message box (mode, model and effort chips, @files, /skills, pictures, queue, stop), its page (name, icon, summary, skills, removal) and a trail of todos, axioms, skills and background jobs. Ctrl+H goes home and Ctrl+1…9 to a project. It stays shut behind a gate until a hired agent is ready, keeps a single window (`crafter summon`), and shows what Painting and Dye lend in item frames.
- **Painting** (`apps/Painting`): the app where agents show a page of HTML, Overworld's take on artifacts. A painting (`Artwork`) keeps its versions and may belong to a group (`Design`), one file per painting in its Chest folder; `overworld:painting paint` publishes one or paints a new version by its id, `show`, `list`, `restore` and `group` read and file them, and painting lights `painting`. Its window drills from groups to paintings to versions, each drawn in a sandboxed `iframe`; it lends its paintings to other apps (`PaintingLender`), pinned to the version painted, and has a chat in a bubble like Dye's (`painting mcp`).
- **The daemon** (`src/Overworld.Daemon`, binary `overworld`): the environment's own process. Hyprland starts it; it keeps the shell and Allay's service running, shines the beacon, keeps the bell's notices and answers the environment's operations, which people and agents reach as `overworld <operation>` and `overworld mcp`, among them pins, bell and `beacon-light`.
- **Seed** (`src/Overworld.Seed`, `overworld:seed`): installs Overworld on an Arch machine: installs the packages it needs (`src/Overworld.Seed/packages.json`, the AUR ones through yay or paru), links its config, themes and the theme worn (keeping the one worn unless another is chosen), publishes the daemon and the apps (Dye, Crafter, Allay and Painting, each with a launcher) only when they changed, builds Glass, and puts them on the PATH.
- **Spawner** (`Overworld.Daemon.Spawner`): starts and supervises processes, Quickshell and Allay's service.
- **Redstone** (`src/Overworld.Redstone`): carries operations between processes, from the shell, the CLI and agents to the daemon.
- **Beacon** (`src/Overworld.Beacon`): signals what changed across Overworld so whoever cares reacts. The daemon shines it on its own socket (`overworld-beacon.sock`, a line of JSON per signal); anyone lights a signal with `overworld beacon light --signal <name>` or the beacon client, and the shell and the apps watch it. Signals so far: `pins`, `theme`, `themes`, `profile`, `agents`, `bell`, `painting`, `crafter` and `crafter-summon`.
- **Bell** (`src/Overworld.Bell`): the notices Overworld dictates, rung by its apps and kept by the daemon in its Chest folder until answered or withdrawn, so they survive a restart. A notice may ask questions (choices, several or one, and words of one's own) or offer buttons (plain, primary, danger); the reply is answered, pressed or skipped. Operations: `bell-ring`, `bell-list`, `bell-answer`, `bell-open`, `bell-withdraw`, `bell-collect` (an app takes its answers and opens); `BellClient` is how an app reaches them. Freedesktop notifications from other apps still come over D-Bus.
- **Pins** (`Overworld.Daemon.Pins`): the apps pinned to the start menu and the taskbar; changing them lights `pins`.
- **The shell** (`config/quickshell/overworld`): the desktop itself, in QML: wallpaper, taskbar, start menu (built once and only shown or hidden), control center, notifications (D-Bus ones and the bell's, answered in a toast or under Waiting on you in the control center), lock screen and captures; it rereads the pins, the theme, the profile picture and the bell when the beacon signals them. Its IPC targets (`qs ipc call menu toggle`, `control toggle`, `lock lock`, `capture open | screen`) are what the Hyprland binds call, except Super, which opens the start menu through the `overworld:menu` global shortcut (`hl.dsp.global`) so no process starts on each press.
- **Hyprland config** (`config/hypr`): the compositor's setup in Lua, with the binds that reach the shell; an untracked `hyprland.local.lua`, loaded last, holds what belongs to one machine.

## Docs

- The GitHub wiki (`dayvsonspacca/overworld.wiki`, its own git repository): how Overworld is built, a page per part and per app, how an operation travels, how an app opens inside another, how a chat works, building from source, the shell, the Hyprland config and the themes.

## Stack

- .NET / C# (`Overworld.slnx`)
- React and TypeScript pages built by Vite, as npm workspaces (`package.json`), with Tailwind
- Glass: Tauri in Rust, drawing with WebKitGTK
- Quickshell (QML)
- Hyprland, with a Lua config
- zsh

## Commands

- `just build` (dotnet build, then the cargo build of Glass)
- `just test`
- `just dev <app>` (runs an app from the sources with its page live from Vite, like `just dev crafter`)
- `just seed` (stop any `just dev` first: both restore the same `obj` folders)
- `npm run check` (type-checks every page)
- On a new Arch machine: `curl -fsSL https://raw.githubusercontent.com/dayvsonspacca/overworld/main/scripts/install.sh | bash` (installs what Seed needs to run, clones the repository and runs Seed)
